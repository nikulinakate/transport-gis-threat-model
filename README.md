# Модель угроз транспортной информационной системы

Демонстрационный проект по разработке модели угроз безопасности информации для условной государственной информационной системы мониторинга транспортной обстановки.

Проект показывает последовательность работ от обследования системы и определения границ моделирования до формирования перечня актуальных угроз, выбора мер защиты и подготовки программы испытаний.

## Состав проекта

- описание назначения и архитектуры системы;
- схема сегментов и границ доверия;
- перечень объектов воздействия и информационных ресурсов;
- модель внешнего и внутреннего нарушителя;
- сценарии реализации угроз;
- реестр из 18 актуальных угроз;
- матрица соответствия «актив — угроза — мера — проверка»;
- программа и методика испытаний;
- реестр конфигурационных единиц;
- порядок отбора и проверки записей БДУ ФСТЭК России;
- скрипт проверки полноты связей между реестрами.

## Нормативная основа

При подготовке материалов учитывались:

- Федеральный закон от 27.07.2006 № 149-ФЗ;
- Федеральный закон от 27.07.2006 № 152-ФЗ;
- Федеральный закон от 26.07.2017 № 187-ФЗ;
- Методика оценки угроз безопасности информации ФСТЭК России от 05.02.2021;
- приказ ФСТЭК России № 17;
- приказ ФСТЭК России № 21;
- приказ ФСТЭК России № 239;
- приказ ФСТЭК России № 31.

Нормативные документы приведены для демонстрации подхода. Конкретный состав требований определяется после установления статуса, назначения и границ реальной информационной системы.

## Условная система

Рассматривается система сбора и обработки сведений о дорожной обстановке. Она принимает данные от внешних источников, хранит транспортные события, предоставляет операторам рабочее место и передает сведения смежным информационным системам.

Система и все приведенные в проекте сведения являются вымышленными. Материалы не содержат данных о реальных объектах транспортной инфраструктуры, конфигурациях средств защиты или результатах аттестационных испытаний.

## Логика модели

Основная цепочка трассируемости:

```text
объект воздействия
→ негативное последствие
→ источник угрозы
→ сценарий реализации
→ актуальная угроза
→ мера защиты
→ метод испытаний
```

Схема архитектуры приведена в `docs/08-architecture.md`. Она содержит внешнюю, пользовательскую, интеграционную, прикладную и административную зоны, а также точки входа и границы доверия.

## Работа с БДУ

Поле `bdu_search_key` в реестре угроз содержит поисковую формулировку для проверки по актуальной версии БДУ ФСТЭК России. Идентификатор БДУ не присваивается автоматически по сходству названия. Порядок проверки описан в `docs/09-bdu-selection.md`.

## Проверка связности

```bash
python3 scripts/check_traceability.py
```

Скрипт проверяет, что каждая угроза связана хотя бы с одним активом, мерой защиты и методом испытаний.

## Ограничения

Это демонстрационный комплект, а не готовая модель угроз для конкретного объекта. Перед применением к реальной системе необходимо провести обследование, определить ее правовой статус, состав обрабатываемой информации, границы контролируемой зоны, актуальные интерфейсы, категории пользователей и фактические средства защиты.
