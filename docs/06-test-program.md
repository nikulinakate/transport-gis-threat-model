# 6. Программа и методика испытаний

## 6.1. Цель испытаний

Испытания проводятся для проверки реализации и эффективности мер защиты, предусмотренных проектной и эксплуатационной документацией.

## 6.2. Условия проведения

До начала испытаний должны быть определены:

- состав и границы объекта испытаний;
- утвержденная схема информационных потоков;
- перечень применяемых средств защиты;
- тестовые учетные записи;
- порядок резервного копирования перед испытаниями;
- ответственные лица и допустимые воздействия;
- критерии прекращения испытаний.

## 6.3. Состав проверок

| Код | Проверка | Порядок | Критерий положительного результата |
|---|---|---|---|
| P-01 | Аутентификация | Выполнить вход с корректными и ошибочными реквизитами, проверить второй фактор | Доступ предоставляется только после успешной проверки всех факторов |
| P-02 | Разграничение доступа | Проверить доступ пользователей разных ролей к функциям и данным | Пользователь не получает полномочия сверх назначенной роли |
| P-03 | Управление учетными записями | Создать, изменить, заблокировать и удалить тестовую учетную запись | Все операции выполняются уполномоченным лицом и регистрируются |
| P-04 | Регистрация событий | Выполнить вход, изменение данных и административное действие | События содержат время, субъект, объект, результат и источник |
| P-05 | Защита журналов | Попытаться изменить или удалить записи без требуемых полномочий | Изменение невозможно, попытка фиксируется |
| P-06 | Сетевая фильтрация | Проверить доступ между зонами по разрешенным и запрещенным направлениям | Разрешены только утвержденные соединения |
| P-07 | Контроль целостности | Изменить тестовый контролируемый файл или параметр | Изменение обнаруживается и формируется событие |
| P-08 | Защита интеграции | Передать сообщение с ошибочными реквизитами и повторным идентификатором | Сообщение отклоняется, причина фиксируется |
| P-09 | Резервное копирование | Создать резервную копию и выполнить тестовое восстановление | Данные и конфигурация восстанавливаются в установленное время |
| P-10 | Управление уязвимостями | Сопоставить состав ПО с результатами сканирования и планом устранения | Критичные уязвимости учтены, сроки и ответственные назначены |
| P-11 | Контроль административной сессии | Выполнить изменение конфигурации администратором | Действие связано с персональной учетной записью и зарегистрировано |
| P-12 | Проверка поставки | Проверить контрольную сумму, подпись и источник тестового пакета | Недоверенный или измененный пакет не допускается к установке |
| P-13 | Защита веб-интерфейса | Передать заведомо некорректные запросы и превысить установленную частоту | Запросы блокируются без нарушения доступности штатных функций |
| P-14 | Защита от вредоносного кода | Использовать безопасный тестовый файл и проверить запрет неизвестного исполняемого объекта | Тестовый объект обнаруживается, событие передается на мониторинг |
| P-15 | Хранение секретов | Проверить права доступа, журналирование и процедуру ротации тестового секрета | Секрет недоступен неуполномоченным учетным записям, ротация подтверждена |
| P-16 | Защита базы данных | Проверить разделение ролей, запрет прямого доступа и регистрацию административного запроса | Доступ соответствует назначенной роли, критичные операции регистрируются |
| P-17 | Учет программных активов | Сопоставить фактические версии компонентов с реестром | Неучтенные компоненты отсутствуют либо оформлены как несоответствие |
| P-18 | Контроль выгрузки информации | Выполнить разрешенную и запрещенную тестовую выгрузку | Запрещенная операция блокируется, разрешенная связывается с пользователем |
| P-19 | Синхронизация времени | Сравнить время компонентов и смоделировать допустимое отклонение на стенде | Отклонение не превышает установленный предел, нарушение формирует событие |
| P-20 | Пересмотр полномочий | Сопоставить выборку учетных записей с заявками и должностными обязанностями | Избыточные и неподтвержденные полномочия отсутствуют либо отозваны |

## 6.4. Форма протокола

| Поле | Содержание |
|---|---|
| Идентификатор проверки | Код из программы испытаний |
| Проверяемый компонент | Наименование и конфигурационная единица |
| Дата и исполнитель | Фактические сведения о проведении |
| Исходные условия | Версия ПО, настройки и тестовые учетные записи |
| Последовательность действий | Выполненные операции |
| Ожидаемый результат | Критерий из программы испытаний |
| Фактический результат | Полученный результат и подтверждающие материалы |
| Вывод | Соответствует / не соответствует / не применимо |
| Несоответствие | Номер записи в журнале замечаний при наличии |

## 6.5. Ограничения

Испытания, способные нарушить доступность или целостность рабочих данных, выполняются на стенде либо в согласованное технологическое окно. Методы проверки должны исключать неконтролируемое воздействие на смежные системы.
