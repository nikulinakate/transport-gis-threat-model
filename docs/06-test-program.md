# 6. Программа и методика испытаний

## 6.1. Цель испытаний

Испытания проводятся для проверки реализации и эффективности мер защиты, предусмотренных проектной и эксплуатационной документацией.

## 6.2. Условия проведения

До начала испытаний должны быть определены:

- состав и границы объекта испытаний;
- утверждённая схема информационных потоков;
- перечень применяемых средств защиты;
- тестовые учётные записи;
- порядок резервного копирования перед испытаниями;
- ответственные лица и допустимые воздействия;
- критерии прекращения испытаний.

## 6.3. Состав проверок

| Код | Проверка | Порядок | Критерий положительного результата |
|---|---|---|---|
| P-01 | Аутентификация | Выполнить вход с корректными и ошибочными реквизитами, проверить MFA | Доступ предоставляется только после успешной проверки всех факторов |
| P-02 | Разграничение доступа | Проверить доступ пользователей разных ролей к функциям и данным | Пользователь не получает полномочия сверх назначенной роли |
| P-03 | Блокировка учётной записи | Выполнить серию ошибочных попыток входа | Срабатывает установленное ограничение, событие регистрируется |
| P-04 | Регистрация событий | Выполнить вход, изменение данных и административное действие | События содержат время, субъект, объект, результат и источник |
| P-05 | Защита журналов | Попытаться изменить или удалить записи с непривилегированной учётной записью | Изменение невозможно, попытка фиксируется |
| P-06 | Сетевая фильтрация | Проверить доступ между зонами по разрешённым и запрещённым направлениям | Разрешены только утверждённые соединения |
| P-07 | Контроль целостности | Изменить тестовый контролируемый файл | Изменение обнаруживается и формируется событие |
| P-08 | Защита интеграции | Передать сообщение с ошибочной подписью, токеном или повторным идентификатором | Сообщение отклоняется, причина фиксируется |
| P-09 | Резервное копирование | Создать резервную копию и выполнить тестовое восстановление | Данные и конфигурация восстанавливаются в установленное время |
| P-10 | Управление уязвимостями | Сопоставить состав ПО с результатами сканирования и планом устранения | Критичные уязвимости учтены, сроки и ответственные назначены |
| P-11 | Контроль административной сессии | Выполнить изменение конфигурации администратором | Действие связано с персональной учётной записью и зарегистрировано |
| P-12 | Проверка поставки | Проверить контрольную сумму и источник тестового пакета | Недоверенный или изменённый пакет не допускается к установке |

## 6.4. Оформление результатов

По каждой проверке фиксируются:

- дата и место проведения;
- проверяемый компонент;
- исходные условия;
- применённые тестовые данные и средства;
- фактический результат;
- подтверждающие материалы;
- выявленные несоответствия;
- вывод о прохождении проверки.

## 6.5. Ограничения

Испытания, способные нарушить доступность или целостность рабочих данных, выполняются на стенде либо в согласованное технологическое окно. Методы проверки должны исключать неконтролируемое воздействие на смежные системы.
